# 2026-06-09

## Port dcs.spa improvements: drag-resizable sidebars + storage-resilient write

Carried the canonical dcs.spa session improvements across to the laradcs
starter kit. Three of the four upstream changes were already satisfied here, so
the work reduced to drag-resize plus a small storage hardening.

- **Drag-to-resize sidebars** (new) — `resources/js/components/dcs/sidebar.tsx`
  + `resources/css/dcs/tokens.css`. Added a `.sidebar-resizer` handle on each
  sidebar's inner edge (10px hit area straddling the 1px `::after` border, 2px
  accent line on hover/drag). React pointer handlers set `--sidebar-width` live
  during the drag (cheap, no context churn) and commit to persisted state via
  `setSidebarWidth()` only on release. Left edge maps `clientX`; right edge maps
  `innerWidth - clientX`; clamped 200–500px to match the existing slider. The
  handle is rendered only while the sidebar is `open`, so the off-canvas inner
  edge never leaks an active strip onto the viewport edge (the bug Codex caught
  in dcs.spa). Hidden below 768px. Complements the existing theme-panel range
  slider — both drive the same shared `sidebarWidth`.
- **Storage-resilient write** — `resources/js/contexts/theme-context.tsx`.
  `saveState()` now wraps `localStorage.setItem` in try/catch (private mode /
  sandboxed iframe / quota) so a failed write can't throw out of the render
  effect. (The read path, `loadState()`, was already guarded.)

Already satisfied upstream-parity items (no change needed):
- **Lucide brand icon** — laradcs is on `lucide-react@1.8.0` (post-brand-icon
  removal) and already ships a custom `GithubIcon` SVG component.
- **Markdown XSS** — no client-side markdown rendering / no
  `dangerouslySetInnerHTML`, so nothing to harden.

Architecture note: laradcs uses a single shared `sidebarWidth` (px) for both
sidebars (vs dcs.spa's independent left/right percentages). Kept that model;
drag drives the same value the slider does.

Verified: `tsc --noEmit` clean on changed files, eslint clean, `vite build` ✓
(780ms). Reverted the `npm install` lockfile drift; left a pre-existing
unrelated `README.md` edit untouched.

## Blank-page diagnosis + dependency consolidation (ducks in a row)

**Blank page was NOT a code bug.** Diagnosed with a throwaway headless
Puppeteer harness against both production (`npm run build` + `php artisan serve`)
and dev (`npm run dev` + serve) — `#app` renders fully (46KB, 0 console errors)
in both. The blank page was a stale `public/hot` file pointing at a dead
`127.0.0.1:5173`; with no Vite dev server actually serving, `@vite` 404s every
asset → empty Inertia root. Removed `public/hot` (gitignored). Reminder: dev
needs BOTH servers and you visit the artisan port, not :5173.

**Dependency consolidation.** Root issue: `npm ci` failed (ERESOLVE) and CI
carried a `--legacy-peer-deps` hack. Real conflict was **ESLint 10 vs
`eslint-plugin-react` (max ESLint 9)** — no plugin release supports ESLint 10
yet, and ESLint is dev-only, so pinned the lint stack to ESLint 9 (latest 9.39.4)
for a clean graph rather than carry the hack.

- npm: `eslint`/`@eslint/js` ^10 → ^9.39.4; `concurrently` ^9 → ^10.0.3;
  `prettier-plugin-tailwindcss` ^0.7 → ^0.8. Regenerated `package-lock.json`
  cleanly (also fixed stale `name: react-starter-kit` → `laradcs`). `npm ci` now
  passes with **no** `--legacy-peer-deps`, 0 vulnerabilities.
- composer: `laravel/ai` ^0.5 → ^0.8.0, `laravel/mcp` ^0.6 → ^0.8.0,
  `phpunit` ^11 → ^13.2. `composer update` pulled latest in-range too:
  Laravel **13.14.0**, inertia-laravel **3.1.0**. Test suite **26 passed /
  63 assertions** under PHPUnit 13 — no config migration needed.
- CI: both workflows switched `npm install --legacy-peer-deps` → `npm ci`.
